## 验证范围

每种宿主都在新的隔离目录中完成 Skill 安装、相同版本重装与 payload 身份检查；数值 Python 环境和已兼容的昇腾工具链复用。机器记录列出的执行文件与服务器实测冻结版本一致，服务器上普通和优化 Python 模式各通过 202 项 CPU 测试，零跳过。

修复前核验原始任务 15 份文件及八份初始内核源码。成功修复要求具备真实失败基线、原生宿主请求、不可变提交快照与绑定源码身份的引擎接纳记录。紧凑集和完整集是两组原始输入；参考实现、seed 0 和各 dtype 容差均保持不变。

宿主交回后，验收控制器使用原始受保护输入和实际接纳源码另建工作区，清洁重建，再执行紧凑集、完整集与全部 51 个完整集用例的逐例新进程检查。最终结论还核对非有限值掩码、原始比较器、原生模块绑定、C++ 完整性、wrapper AST、受保护输入和原始历史未变。宿主回复、安装成功或进度文件均不是验收结论。

与维护版示例字节不同时，精确接纳源码另存为不可变验证快照；源码哈希和验收摘要哈希见机器记录。论文归档与此前的[验证记录](validation.zh-CN.md)保持不变。

## 本次整理的问题

- 用原生 `next`／宿主编辑／`submit` 替代内部 Claude Code worker；模型访问、传输和权限由宿主管理。
- 修复请求明确列出 `precision_tuning/` 下允许的两个审计文件路径。
- Kimi Code 2.2.0 的首次宿主启动因 `--prompt` 与 `--auto` 冲突，在数值修复前退出；非交互 prompt 模式本身已自动执行工具。重试移除冲突参数并使用新安装和新 HOME；失败准备记录保留在机器历史中。
- Claude Code 2.1.204 要求覆盖已有审计文件前先读取。宿主自行恢复后已提交候选；安装指南补充了这一编辑工具约束。
- 确定性子进程过滤已知 provider 凭据环境变量前缀；依赖与运行探针检查实际数值环境。
- 准备环境时，先前已完成但仍存活的容器与后继容器的 `aclInit 507899 / EL0005 Resource_Busy` 同时出现，NPU 进程表仍为空。仅停止经核对空闲、属于本次实验的前驱容器后，原探针恢复。公开 Skill 不执行容器或硬件清理，处理方式见安装指南。

这些结果覆盖记录环境下的原始 Cumsum 测例。请按[当前教程](README.zh-CN.md)在另一台机器上建立自己的结果；任意更大形状、非零 storage offset 视图、通用空输入／溢出／UB 容量处理仍不在本示例的实测范围内。
