# 项目展示网站

网站以中文为默认语言，可在页面内切换 English。HTML、CSS、JavaScript 和精选公开资产都在本仓库的 `website/` 中，直接在此维护。公开仓库以独立历史保存论文冻结 artifact，GitHub Pages 只发布 `website/`。

## 本地预览

在本公开仓库（本地 checkout 为 `public-showcase/`）的根目录运行：

```bash
python3 -m http.server 8000 --directory website
```

在浏览器打开 <http://localhost:8000>，检查中文与英文、手机与桌面布局、图表、图片及链接。静态资产使用相对路径，使本地预览和 GitHub Pages 的项目子路径都可访问。网站无需 npm 安装或构建。

- 所有排行榜或评测 snapshot 必须标注采集日期、硬件、指标口径及分母；更新数字时同步检查图表、正文和中英文文案。
- 当前 CANNBench 成绩属于 2026 年 10 月 15 日封榜的 Season 1。成绩相关的三个排行榜入口指向维护者提供的[原始截图](assets/evidence/cannbench-season-1-a3-2026-10-15.png)，图片不作裁剪或重绘。截图按综合得分排序，本项目第 6；页面中的第 1 指通过数和完整覆盖方案中的通过率排名。JSON 与来源 API 保留原始数据出处，其中 15:14 是数据采集时间，不作为确切封榜时刻。
- 区分 CANNBench 官方结果与论文中早期生成流程（NPUKernelBench 任务）的实验结果，不将不同基准的数字混为同一排名或结论。正式成果链接到原始公开来源。
- 论文中的 PDF 图资产用于说明研究动机、机制和实验，不代表论文全文。论文标题及 arXiv 编号链接到[公开摘要页](https://arxiv.org/abs/2608.02712)，另提供[全文 PDF](https://arxiv.org/pdf/2608.02712) 入口；展示题名和作者机构标号以 arXiv 公开 PDF v2（2026-10-15）的 Accelerator Kernels 为准。

## GitHub Pages 发布

首次由仓库管理员在 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。仓库可见性保持现状；此工作流不会修改它。GitHub Free 的 Pages 需要公开仓库，私有仓库需支持 Pages 的付费方案；即使源码仓库私有，普通 Pages 站点仍公开。

发布工作流为 [deploy-pages.yml](../.github/workflows/deploy-pages.yml)：

- `main` 上的 `website/**` 或工作流自身变更触发发布。
- 也可在 **Actions → Deploy project website → Run workflow** 手动运行。
- 工作流只上传 `website/`，并通过 `github-pages` environment 发布；成功后可在部署记录查看实际网址。

默认项目网址为 <https://Shenxiu-WU.github.io/DRDebug/>。若配置了自定义域名，以 Pages 设置和部署输出为准。

说明参考：[GitHub Pages 自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)、[发布源和公开性](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## 图表与交互

- `dashboard.js` 读取同目录下带日期的公开 JSON；正文保留静态数据作为网络失败时的回退。比较图可切换全量与 Level4，横条统一表示剩余未通过用例，坐标从 0 开始。
- Level4 明确说明为 Official-Tasks 的最高难度等级，包含 8 个复杂算子任务、800 个测例（标准 160 + 隐藏 640）。两列对比直接标明 Debug Agent 与 ForgeKernel 的剩余未通过用例数，避免将 1 和 12 表达为分数；两者覆盖范围一致。
- 首屏将“注意力权重计算（批量 Masked Softmax）”展开为八个主题、九组失败输入：行起点、掩码广播、补齐掩码、归约维度、分块归约、累加精度、指数范围（上溢／下溢两组）和最大值范围。各组仅引入一种缺陷，其余步骤保持正确，不是多种错误叠加或依次修复的轨迹。默认不选中问题，展示十行完整正确代码：拆开加载与 FP32 转换、单独命名最大值，并换行展示归约参数，与 CPU 脚本的六个逻辑步骤等价。浅蓝／浅黄／浅紫／浅珊瑚分别标记索引、掩码、归约、浮点问题的位置，按钮与代码采用一致的颜色。点击主题仅在相应物理行内展开 − 缺陷 / ＋ 补丁，其他九行保持正确；再点同一主题即可收起并恢复正确实现。切换主题只展开当前问题，编号不会变化；多主题共用归约步骤时仍定位到具体参数。
- 右侧保留主题入口、问题与影响摘要和完整代码。选中问题后，首屏两列下方的通栏区域同步展示“问题是什么／代码中如何体现／造成什么影响”、失败输入、指标及输出图；默认收起，不预留空白。提供查看详情的锚点，但选中主题不自动滚动；“收起并复原”按钮恢复正确代码，并将焦点交回原主题。详细证据使用桌面多列、移动端单列，累加精度案例隐藏不适合展示的逐元素图表并使用两列布局。条形图统一 0–100% 刻度；NaN 输出明确显示为失败，不能用零值冒充正常权重。
- 场景展开、收起和补丁行采用 240ms 高度过渡，详情切换辅以轻微淡入，权重横条采用 220ms 宽度过渡。连续操作先读取当前动画位置，再取消旧动画并过渡到最新状态；旧动画回调不能收起新内容，结束后清理临时尺寸与裁剪。收起中的详情暂时不可交互，隐藏状态与按钮语义立即更新。开启“减少动态效果”或缺少浏览器动画 API 时直接切换，初始加载与语言切换不播放展开动画。
- 累加精度案例展示逐次 FP16 舍入：4,096 个零分数产生 4,096 个指数值 1，半精度分母在 2,048 后无法继续累加，权重总和成为 200%；FP32 累加后恢复 100%。这是顺序 CPU 模拟，不能称为特定 Ascend NPU ReduceSum 的实际归约树。指数案例在 FP32 内部计算 `[90,89,88]`／`[-104,-105,-106]`，分别触发 Inf／零分母；减去行最大值后数值稳定。最大值范围案例进一步连接掩码与浮点问题：虽然空位已屏蔽，错误地从原始分数求最大值仍会使有效项下溢；应从屏蔽后的分数求最大值。全部案例统一为 FP16 输入／输出、FP32 内部计算（故障处除外）。输出舍入使非均匀概率之和仅近似 1，完整输出是否匹配参考才是展示的比对标准。
- `repair-demo.js` 执行对应的纯 CPU 数学模型；`repair-explanations.js` 保存九组双语问题、代码位置与影响文案。切换语言保留未选中或已展开的状态，以及指数输入选择。`examples/attention-repair-demo.py` 用标准库 `struct` 建模 IEEE FP16／FP32，使用独立的有效位置参考和最终 FP16 输出比对，保存读取、掩码、指数、归约及完整输出证据。八个主题不是九种独立根因，九组通过也不是修复成功率。示例限定连续行、有限输入、每行至少一个有效位置，全掩码行需另行定义语义。公开稀疏注意力的掩码与归约机制链接到冻结归档；索引、布局、归约、精度与数值范围的相关风险见公开精度知识库。这些是依据机制构造的简化示例，不是实际 Ascend 算子、Agent 历史修复回执或 CANNBench 任务；异步复制、队列、真实搬运对齐等问题仍需设备上的独立证据。首屏保留真实 Cumsum 验证记录入口，原 `examples/fp16-reduction-demo.py` 也保留。
- 首屏数据来源条完整标注 official-tasks、版本系列 1.1 / 任务包 1.1.2、A3 / NPU 910C、标准集与隐藏集、算子和测例覆盖、聚合名及快照日期。算子明细只展示公开的标准/隐藏集聚合计数。
- `script.js` 提供语言切换、修复机制分步说明与论文图放大。首次访问默认中文，之后记住访客选择；无需外部字体或脚本。
- 正文章节依次为「01 真实评测 → 02 研究与方法 → 03 安装与使用 → 04 代码与证据」。「研究与方法」按论文介绍、五步修复闭环、原论文架构图与机制、受控实验结果排列；评测衔接保留原版 NPUKernelBench / CANNBench 双卡片、连接箭头及测试设置与评估重点。架构图默认展示，机制图保留在展开区。`#research`、`#method`、`#paper-experiments`、`#evaluation` 分别指向研究章节、方法子块、受控实验和评测口径，旧链接继续有效。论文的 27 个固定候选与 Qwen 实验、CANNBench Season 1 的 53 个算子与隐藏测试分别说明；原论文 worker 架构与当前 Skill 由编码智能体驱动的实现也明确区分。两张论文实验图以「DRDebug · 定向调试」和「本文方法 / Our method」标记对应结果，另行保留单个连续任务设置。

## 颜色主题

页头的太阳、月亮和显示器按钮分别选择亮色、深色与跟随系统。首次访问保持深色；之后用独立的 `debug-agent-theme` 保存选择，语言偏好不受影响。`theme.js` 在样式绘制前恢复主题，并在跟随系统时响应系统外观变化；禁用浏览器存储时仍可切换。

章节使用全宽底色区分：成果为冷灰，合并后的研究与方法为暖纸色，安装使用为浅绿，资源为灰蓝；深色版有对应的低亮度分区。研究章内通过小标题、分隔线和浅色问题卡区分论文、方法与实验。图表、控件、选中项和弹窗采用统一颜色变量。原论文矢量图保留白底与原始配色。

## 研究内容与任务说明

- 首屏以“算子精度修复智能体 / ASCEND NPU”概括定位；结果正文明确排名对象为测试用例通过数。
- 8个 Level4 算子的功能依据 [Official-Tasks 公开任务定义](https://cannbench.com/api/benchmarks/official-tasks)，实现难点为对其公开计算图的工程概括。详情只显示通过计数、标准/隐藏明细及各任务的功能和难点，不推测隐藏输入。
- 研究区采用当前公开论文 v2 题名、9位作者机构上标及共同第一/通讯作者标记。Token图的口径是总all tokens除以成功算子数：Regenerate为4,372,531,063/11=397.50M，Debug为511,901,478/18=28.44M，降幅92.8456%。包含失败运行和缓存token；M表示百万token。数值来自冻结artifact的token_accounting_summary.json。
- 论文任务和测例单独放在公开 checkout 的 [dataset/](../papers/2026-dont-regenerate-debug/dataset/)，不改写已经打标签的 artifact。此处提供 27 个参考实现、compact/full 公开输入规格及哈希溯源，区别于近成功候选和 NPU 运行环境；网页通过“论文任务与测例”链接到该目录。
- 评测演进分别说明固定公开任务与社区标准/隐藏集的用途，不声称所有27个任务直接来自生产客户，也不把两个平台的数字合并比较。


## 可安装 Skill 展示

`#skills` 保留原有灰绿分区、能力卡、安装命令切换与复制按钮，展示当前智能体驱动修复流程。Codex、Claude Code、Kimi Code 和其他兼容 Agent 分列为四个安装选项；安装目标只选择 Skill 目录，不选择引擎内部模型。Kimi Code 安装到 `~/.config/agents/skills/drdebug`，再用 `kimi --skills-dir "$HOME/.config/agents/skills"` 显式加载 skills 父目录；该参数替代本次会话的用户／项目自动发现，可重复指定以加入其他技能目录。其他 Agent 保留通用 `--dest` 入口，使用编码智能体能够识别的 skills 父目录。

编码智能体沿用已有的模型、工具和对话；CLI 只运行确定性步骤，不启动嵌套 worker 或调用 provider。`next` 返回请求 ID、隔离候选目录与完整指令，智能体编辑候选并在其外部写真实结果 JSON；`submit --request-id ID --result RESULT_JSON` 进行验证和推进。循环到终态后独立 `verify --casewise --json`。智能体的 completed 不表示算子通过。

新 schema-4 工作区默认最多 5 次尝试、86,400 秒总墙钟，包含等待智能体处理的时间与确定性命令；不伪造 turns。旧 run 入口退役，历史工作区只保留原合同下的 status／受支持独立 verify，不热迁移。

统一安装器在 `../install.sh`，当前双语指南在 `../docs/skill-guide.zh-CN.md` 和 `../docs/skill-guide.md`。安装仅需 Python 3.10+ 与标准库；NPU 执行依赖另行说明，doctor 不要求 Claude Code 或其他编码智能体 CLI。模型密钥、权限和 SSH 由你使用的智能体管理。网页不执行安装器或 CLI。

Cumsum 教程与全新安装验证记录分别链接，并随语言切换。智能体驱动修复记录包含真实请求、提交、源码身份与独立 51 例验收；使用公开参考引导，编码智能体配置与验证边界详见结果矩阵。历史验证回执单独保留。安装、环境预检、历史重放和新的真实修复分别表述，论文归档保持不变。
