02 / 研究与方法

“差一点成功”，也是有价值的信息。

我们最新的研究工作关注一个具体问题：当生成的算子已经接近正确，定向调试能否比重新生成找回更多可交付结果？我们在固定近成功候选上研究修复效果与 token 开销，并将这套修复思路延伸到 CANNBench。

最新研究工作 · ARXIV 2026

Don’t Regenerate, Debug: A Domain-Specific Agent for Repairing Near-Miss Accelerator Kernels

这项研究从已有的近成功算子出发，利用失败证据定位问题，通过定向修改与完整验证保留每一轮的有效进展。

方法 / 修复闭环

让修改有依据，让验证有裁决。

大语言模型提出补丁，确定性引擎负责取证、完整验证与结果接纳。一次有效的修复，必须经得起暴露问题的同一套测试。

安装到 ~/.agents/skills/drdebug

先安装到上方 skills 父目录，再用 --skills-dir 启动 Kimi Code 并显式加载。该参数会替代本次会话的用户／项目技能自动发现；如需加载其他技能目录，可重复指定。

指定你的编码智能体能够识别的 skills 父目录。安装器创建 drdebug/，智能体加载 SKILL.md，用自己的工具读取请求、编辑文件并执行 CLI。

准备 → 交接 → 验证

  1. next读取请求 ID、证据、候选目录与完整指令文件。
  2. 智能体编辑修改隔离候选，向 result_file 写真实回复及必要元数据。
  3. submit提交同一请求与结果文件；引擎验证并推进，循环到终态后再独立 verify。

安装后，对智能体说

使用 drdebug 和你当前的模型与工具，创建独立工作区，按 next/submit 请求修复，再独立验证被接纳的源码。

安装与数值执行分别准备

安装仅需 Python 3.10+ 与标准库；数值执行还需 Linux + 昇腾 NPU、兼容 CANN/AscendC、Torch/torch_npu、NumPy 与构建工具。模型访问与 SSH 由你使用的智能体管理，doctor 不检查编码智能体 CLI。

新任务最多 5 次尝试、86,400 秒总墙钟，包含等待智能体处理的时间。智能体驱动的 Cumsum 验证另有完整记录；旧 run 入口已退役。
